This maintenance update hardens **Finder Menu Tools**, the unofficial fork of [MenuHelper by Kyle-Ye](https://github.com/Kyle-Ye/MenuHelper). Please update from v4.0.1.

### Security and data-safety fixes

- **New File cannot overwrite an existing file or link.** Filenames are validated, creation is exclusive and confined to one filename in the opened directory, and new files use mode 0600 subject to filesystem ACLs.
- Shell-copy modes protect metacharacters, quotes, substitutions and newlines. They use spaces between multiple items so a custom separator cannot introduce shell syntax. Literal copy retains its exact-text purpose.
- Full selected paths and clipboard contents are no longer written to public logs. This does not remove historical logs.
- Bookmark access is balanced across reloads, removals and owner cleanup; bookmark errors no longer crash the extension.
- Finder commands use exact immutable entries and validated built-in action keys. Background callbacks read locked snapshots; stale tokens fail closed.
- The Settings shortcut targets this app explicitly, rather than an arbitrary handler of the URL scheme.
- Only recognised permission errors request a folder grant, and custom argument/environment inheritance settings are honoured.
- The settings app uses read-only user-selected file access; write access remains limited to the extension. The unused broad filesystem exception was removed.

### Download

Download **FinderMenuTools-4.0.2-macos-universal.zip**, extract it, and replace the app in Applications. Requires **macOS 15 or later**; includes Apple silicon and Intel binaries. Restart the app and Finder extension when updating. If macOS asks, select the folders you want to authorise again.

The free build remains **ad hoc signed and not notarised**. Follow the app-specific Open Anyway instructions if required; managed Macs may block it. Do not disable Gatekeeper globally.

### Verification and limits

Finder UI checks passed on 9 September 2026 for file/folder Copy Path, opening the selected file in VS Code, Settings with the app closed and running, refusal to overwrite an existing file, and creation of a new empty file with mode 0600. Targeted regression checks cover collisions, symlinks, hard links, traversal, concurrent creation, shell round-trips, resource ownership, action identity and menu snapshots. The GitHub advisory database check found no matches for the two pinned dependencies on 8 September 2026. This review is not an independent penetration test or a guarantee that no vulnerabilities remain. Intel execution and clean-machine first-time installation are not covered by the local testing.
